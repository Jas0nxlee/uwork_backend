## 模型内网解析变化与实际运行

本轮第一次真实 Cron 已触发，但运行在派发前因 `PRIVATE_UPSTREAM` 失败，账目 released、金额及 Token 为 0。诊断发现原模型域名的系统 DNS 已解析为 RFC1918 地址，公共 DNS 仍返回公网地址；两条 HTTPS 模型目录路径均可到达并在无凭据时返回 401。原私网保护正确阻断，不将其误称为模型供应商计费故障。

为恢复用户已授权模型，新增启动项 `PRIVATE_MODEL_ORIGINS`，默认空，严格接收精确 HTTPS origin（含有效端口，无用户信息、查询、片段或非根路径）。只有模型生成和模型探测消费该清单，命中后仅额外允许 RFC1918/IPv6 ULA；回环、链路本地、其他保留地址仍拒绝。每个 DNS 地址仍逐项检查，连接固定已检查地址，TLS 验证和不跟随重定向不变；MCP、企微、网盘和通知出口不消费该清单。

主实例仅为已配置模型加入一个精确 origin，`ALLOW_PRIVATE_UPSTREAMS=false` 保持，其他环境键、主密钥、模型/Agent/已发布安全配置不变。更新前生成在线保护快照，确认没有活动任务后正常关闭、释放租约，再启动最新构建；没有强删租约或修改系统 DNS。实际模型仍解析为私网，受认证的 HTTPS 目录探测与三次生成均成功：

- Cron 使用 Asia/Shanghai 的实际秒/分/时表达式，下一次时间与目标一致；实际只触发一次，模型返回标记，endsAt 后任务禁用。
- 同一会话的两个任务立即连续提交，第二个确实在第一个完成前入队，却在其完成后才开始，并正确读取上一条用户消息的标记。
- 三条账目全部 settled，内部计量合计 **452 Credit，输入 184、输出 268 Token**；初次派发前失败为 0，不产生新增 uncertain。既有 uncertain 记录保留，供应商发票未核实。

新的配置与网络测试覆盖默认关闭、非法 origin、程序化配置失败前不建库、主机/端口/协议精确匹配、RFC1918/ULA 与映射 IPv4、保留网络拒绝及派发前拒绝。真实主实例补充了私网 TLS 正向验证；没有声称已穷尽全部 DNS 混合结果或网络拓扑。
