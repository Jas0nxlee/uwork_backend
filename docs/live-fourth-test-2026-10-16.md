## Host 同步问题与修复

真实磁盘 SQLite/TCP 回归首先复现五个失败：同步回调中更换凭据后仍继续应用；在 policy/models 回调中取消后仍继续；不同组织的配置和目录可能混合；清单为 v1 的保留下载回调却静默返回 v2。独立审查又定位下载和最终事件响应等待期间缺少身份复核，新增两个实际 HTTP 响应交叉测试均先失败。

一次 synchronize 现绑定开始时的终端凭据，所有目录请求使用该身份，应用回调前后检查身份和 AbortSignal。资产下载回调只接受本次清单 ID，绑定版本、身份及取消上下文；下载和最终上报响应返回后再检查，拒绝迟到内容或成功结果。七项回归最终全部通过。原有成功同步和 HTTP 资产合同仍通过，新增三项真实 TCP 传输检查验证 2 MiB 精确边界、超出 1 字节拒绝、302 不转发凭据及预取消不派发请求。

这些是自有 Host 适配器及端口合同的真实 HTTP 验证。测试端口记录应用调用，没有安装或执行原生客户端。已完成的 Host 回调或已派发事件不能由适配器回滚，实际文件/Provider 写入口仍需原 Host 的权限及身份代次检查；不宣称此次已完成原生客户端安装或所有写出口验收。

## 资产分类与版本引用

原删除逻辑只看最新草稿：v1 的分类 A 正在发布时，将草稿 v2 移到 B 就能删除 A，导致当前清单分类悬空；重发布旧 v1 及重新启用遗留停用资产还能再次暴露该悬空引用。四项真实磁盘/TCP 回归分别覆盖启用/停用的当前引用、纯历史分类及遗留启用，修前全失败、修后全通过。

删除现在在同一事务中检查最新草稿与当前选中版本，包括停用资产；纯历史未选中版本不永久阻止删除。发布旧版本和启用资产时检查实际将生效的分类是否仍属于本组织与资产类型，不满足返回 400 INVALID_CATEGORY，资源与不可变版本正文不变。管理员可以发布合法新版本或撤销当前审核后解除引用；遗留停用资产经合法草稿、审核/发布再启用的恢复路径另以实际 API 验证。

## 身份与设备生命周期

五组独立磁盘/TCP 用例全部通过，未发现需要修改身份模块的问题：

- 同一用户切组织后，旧交互 token/cookie 失效，新组织 role/seat/tenant 即时正确；原组织设备仍受原组织规则约束，不能切组织或管理设备。
- replaceId、删除和批量退出只作用于当前用户/组织的设备；误用他租户、他用户或交互会话 ID 不撤销目标，设备不能发起全量撤销。
- 两名 owner 并发自降时，一次成功、一次 LAST_OWNER，始终保留有效 owner；停用再启用不复活旧会话。
- 登录默认 10 次及设备默认 60 次限制、不同组织独立计数、关闭/重开文件数据库后的限制与会话持久化均验证；达到上限时替换失败不撤掉旧设备。

首次重启夹具遇到旧 keep-alive 连接 ECONNRESET，保留原脚本失败记录后用 Connection: close 隔离持久化测试，没有将此测试连接问题冒充产品缺陷，也没有调整生产限流。
