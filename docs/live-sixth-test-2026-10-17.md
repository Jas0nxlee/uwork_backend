## 两处产品问题及修复

Cookie 写入的 Origin 校验曾被非空 Authorization 免除，而认证模块只识别 Bearer，其他方案仍回退 Cookie。真实 TCP/文件库首先复现 Basic + Cookie + 无 Origin 能创建凭据。修复使免检与实际认证来源一致：Basic/未知头回退 Cookie 时仍要求 Origin；无效 Bearer 不回退 Cookie，有 Origin 仍校验 PUBLIC_URL。修后拒绝请求无数据副作用，同源 Cookie 与合法 Bearer 正向路径均通过。302/303/307/308 上游重定向另经实际两端 TCP 验证，目标零请求、没有转发凭据。

飞书通知曾仅凭 HTTP 2xx 标记 sent，真实受控接收端的 code=19024 和非 JSON 响应均复现错误成功。现在 type=feishu 必须满足 HTTP 2xx、64 KiB 内合法 JSON 与数字 code=0；其他响应进入原 DELIVERY_FAILED 重试/截止/上限，不保留远端 msg。冗余 StatusCode=0 不覆盖非零业务码。通用 Webhook 保持原 HTTP 2xx 接受语义。这一合同依据[飞书官方自定义机器人文档](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)；本轮只有受控本机接收端，没有向真实飞书账号发消息，也不把接收端接受当成用户已读。

修前失败与错误持久状态分别保留，修后另用实际 HTTP 验证缺 code 和字符串“0”仍失败、65536 字节合法 JSON 成功而 65537 字节拒绝，远端 msg 不落错误记录；并包含正常关闭/重开文件库、截止前不发送、截止恢复 code=0 后成功且模型/账目仍各一次。其他运行时补测验证 queued Agent 冻结已发布 v1 提示词、新任务使用 v2、停用后队列在派发前拒绝，以及同 Session 串行、跨 Agent/用户绑定拒绝、取消任务不进入后续历史。源码经独立审查，没有跳过或削弱检查。
