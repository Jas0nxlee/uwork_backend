# Mac Native Memory manifest description filesystem admission

The normal signed ARM64 v15 Native client reproduced a product failure under explicit published and effective `filesystem=false`: a local topic file's frontmatter description reached an actual automatic extraction model request. The client used product commit `500914dfe27f96d9db74381c6828244390413281`; this is a separate consumer from the MEMORY.md index admission fixed in that commit.

The owned v2 case completed its five original warm checks, enabled Memory through the original Settings UI, and sent one new four-word Composer task. The unique description marker was absent from that user prompt and from the new task's streamed main request and title request. It appeared only in actual request index 6: a nonstream automatic extraction request with the same complete 32-tool catalog and system context as the task's main request. The supplier continued its original no-tool response; observation did not replace the Memory scanner, scheduler, sender, backend policy, or response handler.

The topic was created through the original xterm shell using a single-line base64 command. Its 154 bytes have SHA256 `bd52e9b0a7f463ce69b8a2d757978978b7a437d2bb7198382184ee09dd6dcfac`; the marker occurs once, solely in `frontmatter.description`. MEMORY.md remained absent. The new session's actual runtime log confirms Memory/use/extraction enabled, the original model, case-owned working directory, and MemoryRoot equal to the topic's directory. The fresh CLI session and warm session are the only two project sessions: no subsequent user task ran after detection.

Before launch and at exposure, the original backend reported published/effective filesystem denied, execution allowed, security version 1 and revision 2. Readonly SQLite SELECTs after shutdown confirm current actor five settled calls, 110 Credit, 60 input and 50 output tokens; these are warm two plus ordinary main/title and the leaked sidecar. Both warm current rows remain unchanged. The other actor's complete ledger, gateway calls and Trace rows remain exactly unchanged at two calls, 44 Credit, 24 input and 20 output tokens. Real request-key digests join gateway calls to ledger; Trace is verified only by its real actor/model/application columns, without inventing a request foreign key.

The case stopped with `MEMORY_MANIFEST_METADATA_ESCAPED_FILESYSTEM_FALSE` after 16.694 seconds. The five warm checks do not make the negative acceptance pass. Fixture exit was 0, cleanup had no errors, OS restoration was verified, all 12 known processes plus the harness daemon were independently absent, four TCP listeners were closed, and the retained harness UNIX socket had no listener. Actual v15 app.asar and zcode.cjs bytes were rehashed against the original manifest; no App or inspector was reopened for this audit.
