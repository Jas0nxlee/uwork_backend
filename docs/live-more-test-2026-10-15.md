## 发现并修复的缺陷

新组织首次读取配置时返回默认投影 revision=0/version=0，但数据库尚无配置行。旧发布接口 UPDATE 影响 0 行后仍插入 version=1 历史并返回成功；再读取仍是 version=0，重复发布会因历史唯一键冲突返回 500。

修复在同一事务中检查 UPDATE 的实际变更行数；未保存草稿返回 409 DRAFT_NOT_FOUND，在历史与发布审计写入前停止。已有草稿的成功发布及旧 revision 冲突语义不变，不自动把默认值实体化为配置。

新增真实磁盘 SQLite/TCP 回归，对 menus、new-chat、assistants、sharing、personal、security、network 七类配置分别验证：重复缺草稿请求稳定 409、投影及历史不变；保存后首次发布版本 1、回执与实际读取一致；迟到发布冲突且不改变历史。修前 7 个子用例全部失败，修后全部通过，父用例也通过。原始失败证据保留；修复由其他 agent 独立复核。

当前运行后端更新前已生成在线保护快照，确认无运行中任务后正常关闭并释放租约，再启动最新编译产物；实际健康与管理页面均为 200。原模型启用、原智能体已发布版本 4、sandbox=true，宿主命令与文件权限继续关闭。

## 配置矩阵与界面清空修复

独立随机端口、临时磁盘库及合成组织执行客户端配置矩阵，覆盖七类配置的首次/并发保存、迟到发布、重复发布、丢弃、个人开关、分享范围、助理渠道、菜单启停、IP/席位/订阅边界。HTTP 记录保留一次测试预期校正：单条 `127.0.0.1` 是规格定义的拒绝全部哨兵，`127.0.0.1/32` 才允许本机；未为满足错误预期放宽产品策略。真实生产构建界面使用两个独立标签页，验证七类配置各六个草稿/冲突/丢弃/发布/恢复分支，共 42 个分支通过。

最终独立记录含 HTTP 94 项（93 个通过断言、1 个保留的旧脚本预期错误）及浏览器 69 项（68 个通过断言、1 个保留的修前界面失败），两个历史失败均附校正或修后通过证据，未删除失败记录。临时实例、监听器、数据库目录、浏览器 profile 均已清理，未改变主实例数据或 Docker 状态。

最后参数边界发现第二个产品缺陷：个人配置的 MCP Hub 支持 URL 或 null，但输入清空后 ValueEditor 发出空字符串，实际保存返回 400 VALIDATION，因此管理员无法从界面清除已有地址。修复只将该字段的空输入转换为 null，普通欢迎语等文本仍保留空字符串；URL 输入保持原文，不扩大后端输入合同。

新增三项真实组件事件回归，经现有 Vite 加载实际 TSX：修前清空用例失败（空字符串不等于 null），另两项正常；修后三项全部通过。测试未增加依赖或修改 TypeScript 编译设置。独立浏览器另以实际 API 检查清空后草稿和发布值均为 null，并检查普通欢迎语空字符串及四种屏幕宽度。测试地址只为 `.test` 元数据，不产生外部 MCP 连接。

## 独立凭据故障验证

新增两项真实临时磁盘库及 TCP 接口测试，使用随机合成主密钥、随机合成凭据和验证 Bearer 的本机模型目录服务，未读取真实供应商密钥：

- 同组织另一个 credential-id 的密文、跨组织密文、认证 tag 翻转，均由模型探测接口返回 503 VAULT_UNAVAILABLE，受控上游请求数未增加；恢复原密文后认证成功。
- 持久库关闭后以错误主密钥重开，探测拒绝且上游零请求，凭据列表无原文；再次以原主密钥重开后认证成功。

密文修改仅为独立测试数据库中的显式故障注入，业务配置与失败/恢复观察走实际 HTTP。测试临时文件、实例和上游监听器均清理。这些测试补持续回归与真实接口边界，不能视作生产主密钥轮换演练。
