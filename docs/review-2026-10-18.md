## 复核确认无问题的要点

- 授权：`preview`、附件 JSON、`/content` 在每次内容请求重查当前成员、同企业、IP 规则、到期与撤销；跨企业/未知 code 一律 404，未登录 401，终端凭据 403；`can_revoke` 与 DELETE 的 write 角色判定一致（owner/admin/operator）。浏览页 HTML 是不含正文的公开壳；登录定位端点匿名只返回完成登录所需的企业 ID，不代表已授权访问正文。
- 限额与配额：能力响应公开上限；20 个未到期准备与每小时 60 次新建在同一事务内校验（探针：第 21 次即 429）；附件数量/单文件/合计与 1 MiB 确认体、64 MiB 企业存储均在分配前校验。
- 幂等与清理：同键同内容重放返回原结果，异内容 409；prepare/upload/confirm 各自的冲突码正确；过期清理把行改为 `expired` 并保留 `client_request_id` 墓碑，重放旧键仍 410 而非重新发布；撤销删除附件字节并清空正文，墓碑保留。
- 浏览页：CSP `default-src 'none'` 只允许同源脚本/样式，正文与附件名均以 `textContent` 渲染，附件下载 URL 必须同源且路径等于预期，下载后校验长度与 SHA-256；受管配置下不写入 localStorage，全局响应 `no-store`。
- 客户端通路：`requestData` 先分流受管 scope，再考虑旧 tokenProvider/ApiClient/默认 fetch；未受管回退只在真实未受管时发生；受管返回 URL 必须是捕获 origin 的 `/share/<code>` 或 `/cn/share/<code>`，附件 URL 必须匹配固定 share/artifact ID；预检/发布/下载/明确拒绝的 continuation 都走私有通路。
