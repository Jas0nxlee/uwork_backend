# 原队列撤回编辑与草稿冲突联动

在既有未打包 Main/Host/共享UI/CLI/真实后台独立夹具中，A在受控供应商暂挂，B原队列删除，C原队列待发。先输入本地草稿再点C编辑：原冲突提示出现，C仍在队列且草稿保持，不能发模型或改账务。清空草稿后点原编辑按钮，CLI确认删除队列项后原Composer恢复C；改为D并重新入队，再释放A，实际供应商只能收到D，不能收到B或原C。

CLI仍是队列命令和执行权威，Renderer只保留原草稿；不注入store/RPC，不替换产品响应。检查实际请求内容、CLI四条持久消息、settled账本及另一成员原行；沿用既有归档删除尾段和自有进程/端口清理。

每轮使用全新profile，`PREPUBLISH_QUEUE_EDIT=1`，保留原240秒预算及各阶段等待。只调用本机受控供应商，不重试历史企微页面或远端综合探针。

排序增量：D重新入队后再经原Composer排队E，用原drag handle物理拖拽E至D前，reload后顺序仍为E/D；释放A后真实主请求必须依次A/E/D，CLI用户消息也同序。预计当前成员4笔settled（含标题）/88 Credit、另一成员既有两笔保持，历史消息6条；不以DOM排序代替执行顺序。使用 `PREPUBLISH_QUEUE_REORDER=1`，保留原预算。
