# 原生个人技能管理入口联测

使用独占 Native 数据根、真实 email HTTP 会话恢复、生产 Main/Host 与正式 CLI。个人技能文件是自有初始输入，不将其存在称为本次创建或导入成功。真实企微、外部 MCP、网盘和付费模型仍排除。

个人技能 list、开关、复制、移除、删除及 prompt 是现有服务入口，后台当前文件/个人/危险技能权限与原身份 scope 约束每个操作。服务层细则见 `clients/uwork/specs/enterprise-skill-management.md`，不能依靠隐藏 UI 或删除后报错冒称阻止写入。已获准发出的文件删除可以完成；撤权后的新派发及旧成功结果必须区分。

Native 验收沿真实 DOM/AX：允许列表后撤销个人权限，点击旧可见技能开关，配置字节保持不变并显示明确拒绝；恢复后可改变开关。删除确认打开后撤权不能删除；取消确认不删除，恢复权限后确认可删除自有技能。技能开关须以技能名称具有可访问名称，并由原 `aria-checked` 表达状态；实际 AX 发现多个无名称开关，是本次需修复的界面问题。

全局文件权限拒绝复用同一 exact-code 文案入口，明确说明文件访问受限，不能误报为个人技能开关关闭；未知错误与包含码字样的任意上游文字保持原诊断。

重复、排队/异步等待、复制/移除、旧 body 取消和 unmanaged 回归由真实临时 FS 与生产私有 session source tests 验证，不用源码测试替代 Native 鼠标交互。测试只读源仓库 out 并拷贝到自有 appRoot，所有进程、端口、目录与专属浏览器 daemon 结束后确认清理。原生目录选择器若锁屏不可用，保留其未验收边界；不绕过锁屏。
