# 同一客户端身份所有者跨组织执行补测

当前 G04k 原生证据只包含目录、配置和用量投影，模型调用为零。本切片补真实后台 HTTPS → 身份服务 → Gateway → ProviderRuntime → Host 私有 relay → 本地供应商 → 后台账本的执行证据，不替代 Native 按钮，也不调用真实企微、外部 MCP 或网盘。

状态沿既有唯一所有者链流转：A 认证 → Gateway 发布 A 目录 → A 实际调用 → 身份服务退出 → 同一加密 store 接受后台验证过的 B 会话 → Gateway 发布 B 目录 → B 实际调用。

验收条件：

- A 首次调用产生一条 settled，7 Token、9 Credit。
- 退出后目录为空；B 完整同步后仅列 B 模型。
- A 捕获的旧 owner proof 在 B 认证后被私有 relay 拒绝，不发送供应商请求。
- 已打开但尚未消费的 A 模型响应在退出、B 恢复后不可读取；B 新请求仍正常完成，旧响应不能变成 B 的数据。
- B 使用当前身份调用自己的模型成功；B 请求 A 模型被后台拒绝，供应商请求不增加。
- A、B 的本人用量与租户账本各只有自己的成功调用，无跨租户读写；拒绝记录单列。
- 网络、身份、Provider 和后台关闭；三监听端口关闭，隔离根清理；证据不记录凭据。

测试身份以隔离后台 email 会话初始化既有加密 store，恢复/退出、网络与计量均使用产品代码。供应商为本机受控 HTTP 服务，不能据此声称第三方模型或 Native 发送通过。

## Native B 原界面发送切片

另开明确的 `UWORK_NATIVE_TWO_ORGANIZATION_EXECUTION=controlled` 模式，仅允许同时启用原双组织登录夹具，计划最多两次本机模型请求（主回答和标题）。默认零调用模式保持不变。沿原空身份 FirstRun、A 登录/退出、B 重新认证链路；使用 browser-harness 的独立 daemon 和该夹具的精确 CDP 端点。

原菜单选择 B 唯一模型，原 Composer 写入固定无工具提示，点击一次原发送按钮。要求原界面显示回答且运行终止；A 的预置账本、调用和 Trace 保持，B 的账本及 Trace 新增与实际供应商请求数量一致，所有行归属 B 普通成员。预置 7/11 Credit 与实际新增金额分列，不使用 React 注入、业务 RPC 代替原发送，不调用真实企微。
